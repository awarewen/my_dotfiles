中国电信宽带测速程序（10000.gd_speedtest.exe）在 Wine 中字体乱码问题排查与解决报告

一、问题现象
1. 在 Linux（Wine 10.20）下运行 `10000.gd_speedtest.exe`，界面部分中文正常，部分位置显示为问号或乱码。
2. 系统 locale 为：
   - LANG=en_US.UTF-8
   - LC_CTYPE=en_US.UTF-8
3. Wine 使用默认前缀：`$HOME/.wine`。

二、原因分析
1. **字体层面**
   - Wine 自带的 Windows 字体有限，程序期望的 SimSun、SimHei 等中文字体在前缀中可能不存在。
   - 虽已存在少量中文字体（如 NotoFangsong），但与程序预期字体名称不匹配，导致回退或显示异常。
2. **编码层面**
   - 中国大陆早期电信类 Windows 程序大量使用 **GBK/GB2312** 代码页。
   - 默认 Wine/系统环境为 UTF-8，若未正确设置系统 locale 或 Wine 内部代码页，程序会按 GBK 解释 UTF‑8 或反之，从而出现问号/乱码。

三、已有修复脚本

1. 字体修复脚本：`~/Downloads/fix_wine_chinese_fonts.sh`
   - 主要操作：
     - 确保目录：`$WINEPREFIX/drive_c/windows/Fonts/` 存在。
     - 从系统字体中查找：
       - 思源黑体（Source Han Sans CN）
       - 思源宋体（Source Han Serif CN）
       - Noto Sans CJK
       - 文泉驿字体（WenQuanYi）
     - 将上述字体链接为 Windows 常用中文字体文件名：
       - `simhei.ttf`、`simsun.ttc`、`msyh.ttf`、`msyhbd.ttf`、`songti.ttf` 等。
     - 写入并导入 Wine 注册表：
       - 路径：`HKEY_CURRENT_USER\Software\Wine\Fonts\Replacements`
       - 将 SimSun、SimHei、Microsoft YaHei、KaiTi、FangSong 等字体名统一映射到 `Source Han Sans CN`。
     - 设置 Wine 内部代码页（部分作用）：
       - 路径：`HKEY_LOCAL_MACHINE\System\CurrentControlSet\Control\Nls\CodePage`
       - 项：`ACP`、`OEMCP`、`MACCP` 设为 `"936"`（GBK）。
   - 额外生成：
     - 启动包装脚本 `~/Downloads/run_speedtest.sh`（后续用 `fix_wine_encoding.sh` 进行了增强）。

2. 编码修复脚本：`~/Downloads/fix_wine_encoding.sh`
   - 主要操作：
     1. 再次将 `ACP/OEMCP/MACCP` 代码页写为 `"936"`，强化对 GBK 的支持。
     2. 给出使用 `winetricks` 安装字体的建议：
        - `WINEPREFIX=$HOME/.wine winetricks corefonts cjkfonts`
     3. 生成通用中文应用启动脚本：`~/Downloads/run_chinese_app.sh`
        - 功能：
          - 自动检测系统是否已生成 `zh_CN.GBK` 或 `zh_CN.GB18030`：
            - 若存在，则设置：
              - `LANG=zh_CN.GBK`（或 `zh_CN.GB18030`）
              - `LC_ALL`、`LC_CTYPE` 同步为相同编码。
            - 若不存在，则回退为：
              - `LANG=zh_CN.UTF-8`
              - `LC_ALL`、`LC_CTYPE` 为 UTF‑8。
          - 设置 Wine 环境：
            - `export WINEPREFIX="${WINEPREFIX:-$HOME/.wine}"`
            - 关闭冗余调试输出：`WINEDEBUG=-all`
            - 禁用部分内置组件：`WINEDLLOVERRIDES="mscoree,mshtml="`
          - 按传入的 EXE 路径切换到其目录并执行：
            - `exec wine "$APP" "${@:2}"`

四、建议操作步骤（实操指南）

1. 运行字体与编码修复脚本（已完成可略）
   - 字体修复：
     - `~/Downloads/fix_wine_chinese_fonts.sh`
   - 编码修复与启动脚本生成：
     - `~/Downloads/fix_wine_encoding.sh`

2. 确保系统已启用 GBK/GB18030 locale
   - 编辑 `/etc/locale.gen`（需要 root 权限），取消以下两行注释：
     - `zh_CN.GBK GBK`
     - `zh_CN.GB18030 GB18030`
   - 重新生成 locale：
     - `sudo locale-gen`

3. 使用 winetricks 安装中文字体（强烈推荐）
   - 安装 winetricks（如未安装，Arch 系：`sudo pacman -S winetricks`）。
   - 在终端执行：
     - `WINEPREFIX=$HOME/.wine winetricks corefonts cjkfonts`
   - 作用：
     - 安装 Microsoft Core Fonts 及常用 CJK 字体（SimSun/SimHei/MingLiU 等），最大化兼容各类老旧 Windows 程序的字体需求。

4. 使用通用中文启动脚本运行测速程序
   - 命令：
     - `~/Downloads/run_chinese_app.sh ~/Downloads/10000.gd_speedtest.exe`
   - 说明：
     - 自动选择 GBK / GB18030 / UTF‑8，并设置相应 locale。
     - 避免直接在英文 UTF‑8 环境下运行导致的编码错乱。

五、若仍存在部分乱码的进一步排查

1. 检查 Wine 字体目录
   - `ls $HOME/.wine/drive_c/windows/Fonts/ | grep -iE 'sim|fang|kai|ming'`
   - 若看不到 `simhei.ttf`、`simsun.ttc` 等文件，说明字体链接或安装不成功，可重新运行字体脚本，或手动将系统字体软链过去。

2. 检查代码页设置是否生效
   - `WINEPREFIX=$HOME/.wine wine reg query "HKEY_LOCAL_MACHINE\\System\\CurrentControlSet\\Control\\Nls\\CodePage" /v ACP`
   - 结果应显示：
     - `ACP    REG_SZ    936`

3. 在不同 locale 下对比运行效果
   - 强制 GBK 运行：
     - `export LANG=zh_CN.GBK LC_ALL=zh_CN.GBK`
     - `wine ~/Downloads/10000.gd_speedtest.exe`
   - 与 `run_chinese_app.sh` 的效果对比，判断是否与系统 locale 或脚本逻辑相关。

4. winecfg 中的图形与版本设置
   - `WINEPREFIX=$HOME/.wine winecfg`
   - 建议：
     - “Applications” 里将 Windows 版本设为 **Windows 7 或 Windows 10**。
     - “Graphics” 里将 DPI 设为 **96**，避免个别控件布局异常。

六、结论

1. 该测速程序的乱码问题由 **字体缺失/不匹配 + GBK 编码环境不完整** 双重因素导致。
2. 通过：
   - 链接及安装常见中文字体；
   - 在 Wine 注册表中设置代码页为 936（GBK）；
   - 使用脚本在启动时自动选择合适的中文 locale；
   可以在大多数情况下消除界面乱码。
3. 若个别字段仍为问号，极可能为程序内部使用“不可显示字符替换”逻辑，或依赖极为特定的 OEM 字体，这属于程序自身兼容性问题，可尝试：
   - 更换 Wine 版本；
   - 在真实 Windows 环境运行测速，仅作对比参考。

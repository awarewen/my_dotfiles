# Agent 操作规范

本文档定义了 AI Agent 在项目中修改和操作时应遵循的规则，确保系统与 Agent 配合统一高效。

---

## 核心原则

### 1. 每一条修改应该有记录和注释

- **代码修改**：所有代码变更必须添加清晰的注释，说明修改原因和影响范围
- **配置修改**：配置文件变更需说明修改目的和预期效果
- **CHANGELOG 记录**：每次重要操作必须在 `CHANGELOG/` 目录下创建对应的记录文件
  - 文件命名格式：`CHANGELOG_主题_日期.md`
  - 内容应包含：操作日期、修改概要、新建/修改文件列表、行为摘要

### 2. 执行修改或删除命令前应该让用户确认

- **危险操作**：删除文件、修改关键配置、执行系统级命令前必须先说明操作内容并等待用户确认
- **批量操作**：涉及多个文件的批量修改需提供操作摘要供用户 review
- **不可逆操作**：如 `rm -rf`、`git reset --hard` 等必须明确告知风险

### 3. 应该理清用户的需求，检查是否存在更优方案，并给出建议

- **需求分析**：在执行前充分理解用户意图，必要时提出澄清问题
- **方案对比**：提供多种实现方案并说明优劣
- **最佳实践**：遵循项目既有规范和行业标准
- **性能考虑**：评估操作对系统性能的影响

### 4. 回复与操作相关时应该清晰明了，便于查看

- **结构化输出**：使用表格、列表等形式展示操作摘要
- **操作前后对比**：清晰展示修改前后的差异
- **简洁准确**：避免冗余描述，重点突出关键信息
- **中文优先**：在中文环境下优先使用中文回复

### 5. 每个 CHANGELOG 风格尽量统一且清晰而详细

- **统一格式**：遵循 `CHANGELOG_主题_日期.md` 命名规范
- **完整记录**：包含操作日期、修改概要、文件变更表、行为摘要
- **交叉引用**：相关文档之间应保持引用正确
- **持续更新**：每次变更都应记录在对应日期的 CHANGELOG 中

---

## 操作流程

### 修改前检查清单

- [ ] 理解用户需求，必要时进行确认
- [ ] 检查是否已有类似实现，避免重复工作
- [ ] 评估操作风险，准备回滚方案
- [ ] 确认需要修改的文件和具体内容
- [ ] 准备 CHANGELOG 记录

### 执行时规范

- [ ] 先展示操作计划，等待用户确认
- [ ] 执行时提供清晰的进度反馈
- [ ] 修改后展示变更摘要
- [ ] 更新相关 CHANGELOG 文件

### 完成后验证

- [ ] 确认操作结果符合预期
- [ ] 检查是否有遗漏的文件或引用
- [ ] 验证相关功能是否正常
- [ ] 提供 review 摘要

## CHANGELOG 模板

```markdown
# [主题] 修改记录

**日期：** YYYY-MM-DD
**Agent：** xxx

---

## 修改概要

简要描述本次操作的目的和主要内容。

---

## 新建文件

| 路径 | 说明 |
|------|------|
| 文件路径 | 文件用途说明 |

---

## 修改文件

| 路径 | 修改内容 |
|------|----------|
| 文件路径 | 具体修改说明 |

---

## 行为摘要

• 操作目标：...
• 主要变更：...
• 影响范围：...

---

## 后续

如有需要持续维护或改进的内容，并添加方便后续agent读取的简要注意事项。
```

- **主要配置目录**：`Config/` 下包含各类应用配置
